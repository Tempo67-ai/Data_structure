# A1 和 A2 代码讲解

A1 解决「一条多行 CSV 记录怎样变成一个文书对象」。A2 解决「从文书中哪一段文字可以确定姓名和律所的对应关系」。A1 输出文书列表，A2 在同一列表的每个文书对象内部填充 `agents`。

## 1. 公共数据结构

- `CaseDocument` 代表一份文书。`docId` 是文书编号，连续编号后可以用 `documents[docId]` 直接取到原文。`caseNo` 是案件案号，同一案号下可以有判决书和裁定书。样例中的编号 0 和 1 对应同一案号。
- `features` 是 `vector<string>`。每个元素是一条完整标签，例如「工资」和「加班」。一份文书内的重复标签合并，供 D2 计算相似度。
- `agents` 是 `vector<Agent>`。一个 `Agent` 一起保存姓名和律所，使 B2 遍历时可以直接建立索引，不必另找两个数组之间的对应关系。

## 2. A1 怎样读 CSV

### `readCsvRecord` 拆出一条记录

`field` 保存正在读取的字段，`fields` 保存已结束的字段。循环每次读取一个字节，用 `inQuotes` 记住是否处于引号内。分隔符是 ASCII 字节，中文正文的 UTF-8 字节沿原顺序加入字符串。流以二进制方式打开，引号内的换行可以按源文件原样保留。

| 读到的位置 | 遇到什么 | 程序动作 |
| --- | --- | --- |
| 引号内 | 逗号或换行 | 加入 `field` |
| 引号内 | 连续的两个双引号 | 消费两个引号，在内容里只加入一个双引号 |
| 引号内 | 单独的双引号 | 退出引号状态，接下来应当是分隔符、记录结束或文件结束 |
| 引号外 | 逗号 | 保存当前字段并清空 `field` |
| 引号外 | 换行 | 保存最后一列，返回完整记录。将外部的 CRLF 当成一个结束标记。 |
| 文件末尾 | 已经读到数据 | 保存没有末尾换行的那条记录 |
| 文件末尾 | 没有新数据 | 返回 `false`，调用者退出读取循环 |

文件开头的 UTF-8 BOM 用三个字节检查并跳过，这样第一列能匹配「标题」。格式异常时抛出错误。使用正式加载函数时，错误会附带文件名及 CSV 记录编号，记录编号包含表头。

举例来说，源文件里的 `"工资,加班""费"""` 是一个字段。外面的双引号用来标记字段，里面的逗号保留，两个成对的引号分别还原，得到 `工资,加班"费"`。

### `loadDocuments` 把每条记录装进结构体

1. 打开第一份 CSV，调用 `readCsvRecord` 读取表头。
2. 用 `columnIndex` 顺序查找「案号」「文书内容」等列名，用找到的下标取值。每条记录的字段数必须与本文件的表头一致。
3. 读取一条数据，用 `normalizeCaseNo` 统一全角括号并去掉常见空白。用 `splitFeatures` 按换行切分标签，去掉两端空白，再用顺序比较去重。
4. 构造 `CaseDocument` 并填充各字段。加入文书列表前，把列表当前长度作为 `docId`。`std::move` 把已有正文字符串的内容交给文书对象，避免再复制一遍长正文。
5. 按参数顺序读下一份文件。共同使用同一个 `documents`，编号因此跨月连续。

A1 对 CSV 字节顺序扫描一次。假如一份文书有 `k` 个标签，用顺序表去重最多比较约 `k²` 次，适合这里每份文书的短列表。

## 3. A2 怎样提取律师和律所

### 第一步，定位文书里的署名行

`extractAgents` 按正文换行遍历。包含「律师事务所」的行才进入下一步。若同一行用分号隔开多个署名，各分句单独检查。`parseAgentClause` 识别「委托诉讼代理人」「委托代理人」「诉讼代理人」「辩护人」等角色，也允许角色前有「原告」「被告」「共同」等常见前缀。这样可以排除许多正文里仅提到该角色的叙述句。

### 第二步，用分隔符截取两个字段

例如下面这一行：

```text
被告委托诉讼代理人：何宁，滨城示例律师事务所律师。
```

1. 从角色词之后开始取文字，有冒号就跳过。源数据里也有直接在角色后面写姓名的格式。
2. 找到第一个中文或英文逗号，左边是姓名，右边下一字段应包含完整的律所和职业说明。
3. 截取到「律师事务所」为止作为律所名，再检查后面是否是「律师」「专职律师」「执业律师」或「兼职律师」等明确的职业说明。
4. 姓名段含顿号时，把多个姓名分别配给这一分句明确写出的同一家律所。常见匿名标记及不符合当前姓名格式的条目跳过。「…，男。」这类条目没有明确律所和律师身份，也会跳过。
5. 将姓名和律所一起放进 `Agent`。`appendUnique` 用顺序查找检查同名且同律所的配对是否已经加入。若姓名相同而律所不同，两条都保留。

`isClearName` 对常见中文姓名做字符检查。它逐组三个 UTF-8 字节还原常见汉字的编码值，并单独允许出现在姓名中间的间隔点。这里的姓名规则仅用于提高当前格式匹配的明确性。生僻扩展汉字、用拉丁字母书写的姓名、跨行署名、未列明律所或其他职业表述，可能需要单独增加规则。实习律师按当前口径未计入。匿名片段和其他未识别文本仍留在原正文。

### 第三步，把配对写回每份文书

`populateAgents` 遍历文书列表，把 `extractAgents(document.content)` 的结果赋给该文书的 `agents`。使用赋值后，同一批文书重新跑 A2 会替换原结果，配对不会每次多一份。

A2 按正文逐行扫描。每份文书通常只有少量代理人，用 `vector` 逐条检查姓名与律所即可。算法识别的是**文书中明确写出的关系**。输出为空时，可能是原文没有相关律师，也可能是原文写法超出了本版规则。

## 4. 运行核对

| 验收项 | 已运行结果 |
| --- | ---: |
| 四条联调样例 | 4 份文书，3 份有配对，合计 4 条配对 |
| 1 月 CSV | 4,952 份文书 |
| 1 月第一份文书 | 日期为 2024-01-02，正文保留 34 个换行 |
| 12 个月全量 CSV | 40,900 份文书，编号为 0 至 40,899 |
| 全量中有案情特征的文书 | 15,715 份 |
| 民事一审判决书 | 7,895 份，其中 7,588 份有案情特征 |
| 全量文书中 A2 识别出的配对 | 10,656 份文书有配对，按文书累计 17,184 条 |
| 民事一审判决书中有 A2 配对 | 3,633 份 |

A2 最后三项有关配对的数据用于核对运行规模。要估计识别准确率或漏识别比例，可以分层抽取有结果和无结果的文书，逐条人工标注后对照。
