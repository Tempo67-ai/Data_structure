# D 模块 · 共同参与案件与相似案件

## 验收

从仓库根目录运行 `make -C court_module_d check`，需要 C++17。测试使用 A 提供的四条虚构 CSV，先调用 `loadDocuments` 和 `populateAgents`，再验证 D 的两个接口。

- D1 中，林小川与何宁共同参与 `(2024)津00民初1号`，结果包含文书 0。林小川与周青没有共同参与的案件。附加用例验证裁定书过滤、同案号归并及重复编号。
- D2 以文书 0 为查询，依次返回文书 2 和 3，相似度分别为 1/2 和 1/3，共同标签均为「工资」。附加用例验证缺失字段、候选筛选、去重和前五份的同分排序。

## 接入 B2 和 E

把 `court_module_d/CaseAnalysis.cpp` 加入已有的 A 模块编译目标，并将 A、D 目录都加入头文件搜索路径。菜单或详情页引入 `CaseAnalysis.h`。文书编号沿用 A 的 `docId`。

- **D1** 调用 B2 两次，按「姓名＋律所」分别得到 `firstLawyerDocIds` 和 `secondLawyerDocIds`。把它们与文书列表传给 `findSharedCases`。菜单项使用「共同参与案件」，按结果的 `caseNo` 展示，需要查看详情时使用 `docIds`。空列表可显示「没有共同参与的案件」。当前验收程序用样例配对构造 B2 的返回值。
- **D2** 把详情页当前的 `docId` 传给 `findSimilarCases`。每条结果包含候选文书的 `docId`、分数和共同标签。状态为 `MissingFeatures` 时显示「缺少案情特征，无法比较」，为 `MissingCause` 时显示「缺少案由，无法比较」，为 `DocumentNotFound` 时显示「未找到文书」。状态为 `Ok` 且结果为空时显示「没有可比较的文书」。

## 算法

- **D1** 用两个 `vector<int>` 保存 B2 的编号列表，排序后通过双指针求交集。再从文书列表中筛出交集里的民事一审判决书，按 A 的案号规范化规则汇总，保留同案的文书编号。
- **D2** 在民事一审判决书里筛选同案由、不同案号且有标签的文书。每份文书的标签先去重，再顺序比较得到交集。Jaccard 分母为「查询标签数＋候选标签数－共同标签数」。按相似度从高到低返回最多五份，同分按文书编号升序，标签无交集时分数为 0。
